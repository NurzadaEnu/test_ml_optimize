# test_ml_optimize

ML pipeline for optimizing the operating mode of hydrotreating reactor R-1 (unit LG-35-11/300-95), revised after peer review. XGBoost surrogate models predict the hydrogenate volume and the product-quality indicators from the operating parameters x1–x5. A single optimization problem is then solved: maximize volume subject to a required quality level.

> ⚠️ The project runs on **synthetic data** generated by a physically grounded surrogate of the unit. Models trained on it inherit its limitations; applying them to the real unit requires retraining on plant data with a time-ordered split.

## Changes made in response to the reviewers

| Comment | Change in the code |
|---|---|
| R1-1 | Volume: `y1 = x1·η(x2,x3)`; η is least-squares calibrated on the three reference modes of Table 1 (76.0 / 77.5 / 77.0 m³/h); η ≤ 0.995 ⇒ `y1 < x1` everywhere |
| R2-6, R1-3 | μ1–μ3 are reaction conversions from Arrhenius kinetics calibrated at the **centre** of the operating ranges. They are not centred on the AorRA+PO solution; the generator contains no information about the optimum |
| R1-4, R2-4 | Single problem (Eq. 16) with the explicit constraint `y1 ≤ x1`; the two-stage lexicographic formulation is removed; volume–quality front (ε-constraint) |
| R1-5 | All Table 1 modes are evaluated on one common quality model (`data/table1_common_model.csv`) |
| R1-2, R2-3 | Fig. 5: sensitivity of volume and Score to temperature |
| R2-7, R2-11 | Test RMSE / R² / MAE (80:20) and 5-fold CV R² ± std; `TimeSeriesSplit` for real data |

## Variables

| Input | Description | Range |
|---|---|---|
| x1_feed | feed rate, m³/h | 45–80 |
| x2_pressure | pressure, kgf/cm² | 20–35 |
| x3_temperature | temperature, °C | 300–343 |
| x4_lhsv | liquid hourly space velocity, h⁻¹ | 0.5–5 |
| x5_h2_ratio | hydrogen-containing gas, H₂/HC, nm³ | 200–500 |

| Output | Description |
|---|---|
| y1_volume | hydrogenate volume, m³/h |
| mu1_unsaturates | conversion of unsaturated hydrocarbons (hydrogenation) |
| mu2_sulfur | desulfurization conversion (HDS) |
| mu3_acids | removal of acidic compounds |

Quality criterion: `Score = 0.35·μ1 + 0.40·μ2 + 0.25·μ3`, threshold `Score ≥ 0.90`.

## Structure

```
generate_data.py    # 1. synthetic dataset (3000 rows): yield balance + Arrhenius kinetics
train_model.py      # 2. four XGBoost models (y1, μ1, μ2, μ3), 80:20, RMSE/R²/MAE
validate_model.py   # 3. 5-fold CV (R² ± std), surrogate vs generator check
optimize.py         # 4. Eq. 16, Table 1 on a common model, Fig. 5, leakage check
compare_models.py   # comparison of 8 algorithms (LR, Ridge, KNN, RF, GB, XGBoost, LightGBM, MLP)
data/               # dataset and result tables
plots/              # parity, feature importance, model comparison, Fig. 5
```

## Quick start

```bash
pip install -r requirements.txt
python3 generate_data.py && python3 train_model.py && python3 validate_model.py && python3 optimize.py
```

Trained models (`models/*.joblib`) are not stored in the repository; `train_model.py` creates them.

## Moving to real plant data

1. Replace `data/synthetic_dataset.csv` with a real CSV that has the same column names.
2. Run `python3 train_model.py && python3 validate_model.py && python3 optimize.py`; `generate_data.py` is no longer needed.
3. In `validate_model.py`, use `cross_validation(df, time_ordered=True)` for a time-series (block) split.
4. Narrow `generate_data.BOUNDS` to the ranges actually observed in the historical data.

See [HOW_TO_RUN.md](HOW_TO_RUN.md) for details.
